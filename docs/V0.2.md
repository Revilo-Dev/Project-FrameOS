# FrameOS v0.2 validation and TV acceptance

For the subsequent wallpaper/UI and native USB fix, see [the refresh notes](V0.2-REFRESH.md). The sections below describe the original v0.2 release.

The redesigned Home has one centred 24-hour Brisbane clock and date, real cached Open-Meteo weather, and names inside the eight app tiles. Settings preserves v0.1 preferences and adds six Australian weather locations. Narrow browser windows use two dock rows; lateral arrows still reach all eight apps, and Down always opens Media Hub.

Media Hub uses the existing central remote handler. It discovers mounted external storage, reads the selected root, and enumerates a child directory only when opened. Parent-folder focus is restored from stable entry IDs; file details retain the selected entry so a future player needs no rescan. The grid renders a bounded three-row window, scrollable by arrows or mouse wheel; no recursive index is built. Filters preserve folder access. Refresh invalidates directory caches; removal clears affected entries and stale details. USB files are never written, deleted, moved or renamed.

The native adapter uses `listStorages`, read-only `resolve(..., 'r')`, `File.listFiles`, and storage listener registration/removal through the platform boundary. Samsung documents write permission for listener APIs. This release requests no write privilege: if listener registration is denied, it compares read-only storage snapshots every five seconds only while Media Hub is open. API timeouts, permission denial, inaccessible/unsupported drives, invalid entries and removal during reads return explicit states. Real-TV callback timing, filesystem support and responsiveness remain unverified.

The browser development fixtures require `npm run dev` and explicit `?mockUsb=1`. Production removes fixture construction. Automated browser tests inject a controlled Tizen API independently of shipped code and route deterministic weather responses. Test screenshots demonstrate layout, not real connected storage or current weather.

Review [the policy diff](../tizen/config.xml.v0.2.diff) and [explanation](../tizen/README.md). The protected original manifest stays unchanged; only local packaging copies gain the required privileges/access/CSP. Application ID, package ID, widget version, icon and original metadata remain intact. Existing author identity checks are preserved; `revilodev-frameos` is the matching profile, despite the older prompt's `frameos` name.

Local validation and signed packaging:

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run check:tv
node scripts/tv.mjs package
```

No install/launch occurs in these steps. `stage:tv` and `deploy:tv` remain separate explicit commands. Package mode does not modify the external Tizen project.

Completed local validation: strict TypeScript checks, all 70 unit/pipeline tests, all 11 production-browser tests, Chromium 69 build verification, the installed Tizen web build, signing and archive verification. `check:tv` confirmed the expected TV and matching existing author profile. All 24 external Tizen project files still match the original/v0.1 ownership records.

No installation or launch was performed. Native USB behaviour and live weather on the physical TV still require the acceptance checks below.

After approval for a TV update, use `npm run deploy:tv`, then verify:

1. Clock/date, live Brisbane weather, Settings location changes, cached forecast after losing connectivity, wallpaper/theme/motion persistence.
2. Each dock tile, rapid arrows, Down from different tiles, Settings normal navigation, and exact Home focus restoration after Back.
3. No USB prompt, insertion, multiple drives, top-level entries, nested/empty folders, breadcrumbs, filters, Refresh and long filenames.
4. MP4/MKV details show size, storage, parent, virtual path and resolved URI without attempting playback.
5. Large directories stay responsive with a bounded visible grid; Back restores the correct folder/file position.
6. Remove a drive while loading, browsing or viewing details. Confirm stale entries disappear and another drive or the connection prompt remains usable.
7. No filesystem writes, automatic startup, firmware changes or system-setting changes.
