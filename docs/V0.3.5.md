# FrameOS v0.3.5 — One UI interface refinement

This release changes presentation and remote navigation, including the requested follow-up transport controls and seek increments. The existing uncommitted v0.4 media work was present when implementation started and is preserved. The native playback engine, USB caching, thumbnails and startup behavior are unchanged. Frontend package metadata is v0.3.5; Samsung application/package/widget identifiers and the existing packaging policy are unchanged.

## Interface

- Seven existing shortcuts remain in the dock; USB media continues to use the existing downward Media entry. Branded 104px squircle icons expand to 290px on actual focus, keeping the full title inside. A single flex row reserves enough space for every icon. Width, label opacity and elevation animate for 200ms. Memoized tile components update the old/new focused icons without rerendering unrelated tiles.
- Shared materials, white focus borders, radii, typography, disabled states, spacing and motion live in `src/styles/oneui.css`, loaded after the existing styles. No component or animation dependencies were added.
- Clock Font provides Modern, Rounded, Minimal, Bold and Digital, plus the original Classic serif. Static local numeral subsets total 34,724 bytes; licenses and source attribution are bundled in `public/assets/fonts/clock-LICENSES.txt`. Font changes preview immediately and persist in the existing settings record. Fixed time/date line boxes preserve alignment; local fallback stacks cover font-loading failure.
- Settings is a 1360 × 920 floating panel on the 1920 × 1080 stage. Its background uses the existing preblurred wallpaper asset. Content scrolls internally, including automatic scrolling for remote focus. Existing Appearance, Clock, Wallpapers, Weather, USB diagnostics and Media settings remain available.
- Channel Up advances Settings tabs and Channel Down reverses them, with wrapping and per-tab focus memory. D-pad/Enter and desktop Page Up/Down remain alternatives. The existing central `useRemote` listener routes both Settings and player controls. App owns one context-dependent registration. Native text editing bypasses navigation routing.
- Media Hub has a Home indicator, breadcrumbs and one Options button. The menu contains file filters, natural/episode ordering, ascending/descending natural filename ordering, Show Hidden Files, Refresh and selected-item actions. Filters/sorting/visibility operate on existing directory data without rereading USB.
- Back closes Options first, then traverses parent directories, then returns Home from the root. Up moves from the grid through breadcrumbs to the header; only a further Up from the Home/Options header exits. Selecting Home also exits directly. The existing vertical page transform reverses on return and restores the launcher origin.
- Folder cards use a local SVG icon, two-line CSS ellipsis, complete original filenames and the shared white focus outline. Their dimensions and grid positions remain fixed on focus. Full names remain available in the focused title, title attribute and item details.

## Player transport controls

The five circular controls are **Previous · −10 · Play/Pause · +10 · Next**. Previous uses the exact Next SVG mirrored horizontally and moves to the previous entry in the existing episode queue. It is disabled at the first episode; Next is disabled at the last. The remote Back button still closes playback and restores the selected library entry. Play/Pause remains white; the other controls keep their darker colouring. The persistent control hint is removed, while accessible names describe each action and playback state.

| Input | Action during playback |
| --- | --- |
| −10 / +10 controls | Seek backward / forward 10 seconds |
| Volume Down / Up | Seek backward / forward 20 seconds |
| Left / Right with the timeline focused | Seek backward / forward 30 seconds |
| Channel Down / Up | Existing backward / forward 30-second seeks |
| Media Rewind / Fast Forward | Existing backward / forward 10-second seeks |

Volume keys are discovered and registered only during playback, using [Samsung's TVInputDevice API](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/tvinputdevice-api.html). They are not captured in Settings, the browser or Home; Mute remains untouched. Registration failures leave the on-screen buttons and timeline usable. Cleanup releases the native and named key mappings. All seek paths use the existing AVPlay gate and endpoint clamping, preserving pause and preventing overlapping native operations.

## Deployment

The successful deployment pipeline is unchanged. It uses the existing **`revilodev-frameos`** certificate profile; the repository documents that the profile named `frameos` has a different author and cannot update the installed application. Do not switch profiles or regenerate certificates.

For an optional local signed package, without installing or changing the source Tizen project:

```powershell
node scripts/tv.mjs package
```

After explicit approval to update the physical television, run:

```powershell
Set-Location 'C:\Users\revil\StudioProjects\frameos\Project-FrameOS'
npm run check:tv
npm run deploy:tv
```

The configured target remains `192.168.0.23:26101` / `QA32LS03TBWXXY`. The deploy command rebuilds, stages, signs, verifies author continuity, installs and launches using the original identifiers. See [deployment details](DEPLOYMENT.md).

Physical Tizen 5.5 rendering, remote channel-key availability and native video decoding still require testing on the Samsung Frame after approval. Desktop fixtures validate routing and native API calls, not actual hardware decoding. Unsupported launcher integrations retain their existing honest unavailable notices. No TV installation, firmware change, Developer Mode change, automatic startup or USB-file modification is part of this implementation.
