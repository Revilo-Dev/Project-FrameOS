# FrameOS v0.3.6 — Widgets

[Changed files and verification](V0.3.6-FILES.md) · [33-screen reference gallery](../artifacts/screens/index.html)

The Home clock remains a permanent, centred element. Settings → Widgets controls Weather, Calendar, Reminders, To-do and World Clock. Zero to three widgets can be active. Left/right ordering controls apply to the enabled row; the layout centres one or two cards and balances three cards above the existing dock.

From the dock, Up reaches the widgets. Left/right selects a widget, Enter opens its floating panel and Back restores focus to that card. Up again reaches the top controls. Down from the dock still opens Media Hub. Settings retains Channel Up/Down tab switching and D-pad navigation; player channel, volume and transport mappings are unchanged.

## Available now

- Weather uses the existing Open-Meteo request, 45-minute per-city cache and offline fallback. Daily high/low temperatures sit at the right of current conditions, using the selected city’s local forecast day in the same API request. Old caches remain usable offline and upgrade on a successful refresh; unavailable daily values display dashes. Vector icons follow actual WMO codes and use restrained weather colours. Cards reuse the wallpaper's existing pre-blurred image; there is no live backdrop blur. New Beith remains available in Weather settings.
- Reminders have a title, due date/time, completion and removal. To-do has titles, completion and removal. Both persist locally on the TV, separately from Calendar. Each list is bounded at 200 entries. Titles are limited to 160 characters and wrap inside detail panels.
- Date/time inputs use the main clock's selected timezone. Invalid dates and nonexistent times during a daylight-saving jump are rejected. A repeated time during the autumn transition resolves to one valid occurrence; change the main timezone before entering a reminder if a different local zone is intended.
- World Clock defaults to Brisbane, Warsaw and New York. Select one to three cities from the offline city list. IANA timezone rules adjust the date and daylight-saving offset. Clock updates pause when the app is hidden.
- Calendar provides a remote-accessible month view, selected day, a seven-day agenda surface and persistent Privacy Mode. Privacy Mode hides event titles in both dashboard and panel views once an event source is connected.
- Preferences use `frameos.widgets.v1`; tasks/reminders use `frameos.organiser.v1`. Existing launcher, weather, clock and media preference keys remain intact. Storage failures are reported as session-only changes.

## Google Calendar deliberately deferred

Per the release instruction, the Google Calendar API and account connection will be added later. This build does **not** authenticate an account or display fabricated events. The Calendar card and panel clearly report that the connection is coming later. Refresh is disabled while unconfigured. Browsing months works offline.

There was no companion backend in the repository. This release defines a typed read-only provider and HTTPS companion adapter in `src/services/calendar.ts`, with mapping, response validation, caching, permission-expiry and disconnect handling. `useCalendar` supplies visibility-aware refresh scheduling for a future configured provider. The app currently uses `pendingCalendarProvider`, which makes no network requests and does not read stale personal cache entries.

The adapter is a boundary for future integration, **not a deployed OAuth backend**. No API keys, client secrets or Google access/refresh tokens are bundled or stored on the TV. See [Google Calendar integration contract](GOOGLE-CALENDAR.md) for the deferred server work and exact Cloud setup steps. No credentials are needed for this release.

## Compatibility and verification

Target: Samsung The Frame QA32LS03TBWXXY, Tizen 5.5 / Chromium 69, 1920 × 1080. No new dependencies. CSS uses supported variables, flex/grid, ordinary radii and transform/opacity transitions. The classic offline Vite build and its asset/syntax verification remain in place.

Run:

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
```

There is no configured lint command. Automated checks cover widget limits/order/persistence, empty layouts, local lists, timezone/DST boundaries, read-only Calendar mapping and errors, Settings navigation, and existing USB/AVPlay/player behaviour. Google account authorization and real calendar synchronisation require the later backend integration. Samsung on-screen keyboard behaviour, sofa readability, timezone database coverage and performance on the physical TV still require device testing.

## Deployment

The production frontend is `dist/`. The existing deployment scripts, application/package identifiers, Tizen manifest policy, certificate and external Tizen project are preserved. No TV installation is performed by this release task.

After explicit approval to install on the TV, use the existing command:

```powershell
Set-Location 'C:\Users\revil\StudioProjects\frameos\Project-FrameOS'
npm run deploy:tv
```

This pipeline verifies the pinned identity, builds, stages, signs, installs and launches. Keep its existing `revilodev-frameos` author certificate profile; switching to the differently signed `frameos` profile would break updates. See [deployment guide](DEPLOYMENT.md) for the existing checks and rollback procedure.
