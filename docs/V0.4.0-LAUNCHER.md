## Features and default dock

All seven feature groups are implemented: All Apps; dock editing; separate TV/FrameOS Settings; Sources; Art/Gallery gradient; Browser gradient; and a protected TV shortcut.

The default order is:

1. Art Mode
2. YouTube
3. Stan
4. Prime Video
5. Gallery
6. Browser
7. TV Settings
8. Sources
9. TV
10. All Apps

Approximately seven fixed-width cells are visible. Left/Right scrolls further entries into view. Expanding the focused squircle does not resize its cell. Reordering uses brief transform animations. Art Mode stays first; Art Mode, TV and All Apps cannot be removed. TV and All Apps can move within the scrollable dock. Migrated custom shortcuts are retained, so an upgraded dock may differ from this default.

Actions distinguish FrameOS screens, discovered installed apps, Samsung system shortcuts and user pins. IDs remain stable through reordering and restarts. The top-right gear is labelled **FrameOS Settings** and retains appearance, wallpaper, clocks/widgets, media, dock configuration, recovery and diagnostics. The dock Settings tile is labelled **TV Settings**.

Art Mode and Gallery use an orange/pastel-pink/lavender diagonal gradient with white artwork. Browser uses violet/royal-blue/electric-blue and the globe icon. No wallpaper, full-screen Art Mode or Samsung Art Mode behavior was changed.

## Remote controls and app management

- Left/Right moves dock focus. Short Select opens on release.
- Up opens the focused tile's Options menu: Open, Move, Remove when allowed, App information, and a route to the FrameOS Settings gear. Up again from the first option focuses that gear.
- Hold Select for 600 ms **with at least one further Select keydown** to enter Move Mode. Both `repeat=true` and repeated numeric Tizen key events with `repeat=false` are recognized. Select release ends the held gesture without opening the app.
- In Move Mode, Left/Right changes position; a fresh Select confirms; Back cancels. Draft order is not persisted before confirmation. Mouse activation during Move Mode also confirms placement. Tab cannot move focus out of Move Mode.
- A long Select without repeat evidence does not launch an app. If keyup/repeats are absent or inconsistent, use **Up → Move** or **Up → Open**. Real remote event behavior remains a physical acceptance item.
- All Apps uses a five-column scrolling grid. Select or Options opens app actions. **Add to Dock** updates immediately; **Remove from Dock** removes the corresponding pin. Duplicate additions are ignored. Native app versions/IDs are shown when reported.
- All Apps caches its consumer catalogue until Refresh. Internal destinations remain available when native discovery fails. Native consumer destinations appear only when actually discovered. Background services, FrameOS itself and reserved system components are filtered. Native icon paths have a packaged icon fallback if unreadable.
- Restore Default Dock requires a separate confirmation; Back/Cancel preserves the existing dock.

One remote listener owns Select and navigation. It suppresses repeated Select activations and keyboard ghost clicks, and cancels holds on focus loss or visibility changes. The existing hold implementation's browser timer binding was repaired. Samsung retains volume, physical Home and Power ownership. Media Channel Up/Down seeking remains unchanged.

## Samsung integration evidence

**TV Settings:** public launchability on this physical TV is **unverified**. Selection refreshes real `application.getAppsInfo()` data and verifies only `com.samsung.tv.coba.setting`, then tries `application.launch()` and its supported AppControl fallback. The original error/API result is recorded in launch diagnostics. Even an accepted callback produces a verification/fallback notice. Missing, denied, unsupported and accepted outcomes have mock coverage. The fallback directs users through the protected TV tile to Samsung Home → Settings. No alternate component is substituted.

**Browser:** installed-app discovery must verify a candidate before launch; discovery failure does not fall back to an unverified browser ID.

**TV:** opens only `com.samsung.tv.csfs`, the component previously physically verified by the owner. This patch verifies the exact request in mocks and preserves Settings → Open Samsung Home. The new dock shortcut itself still needs physical acceptance.

**Sources:** reads the actual `VIDEOSOURCE.connected` and `.disconnected` arrays. No port or connection state is invented. `tvwindow.getSource('MAIN')` supplies the current-window highlight and nullable signal information when available. It is not proof of Samsung Home's global source state.

Selection revalidates the reported port, requests `setSource()`, and separately requests `show()` at `['0', '0', '100%', '100%']`, `MAIN`, `FRONT`. This is a public TVWindow display request within FrameOS, not a claim that global input ownership changed. Its status explicitly requires picture verification. Back calls `hide()` before leaving the source view; errors retain a Samsung Home → Source fallback. Missing APIs, denied calls, timeouts, absent ports and failed display requests do not claim successful playback.

The user explicitly approved exactly `<tizen:privilege name="http://tizen.org/privilege/tv.window"/>` during this session. This is the sole manifest difference from the existing v0.3.8 packaging policy. See [approved diff](../tizen/config.xml.v0.4.0-launcher.diff) and [packaging preview](../tizen/config.xml.v0.4.0-launcher.preview). It is applied only to the fresh packaging copy.

Official references: [Samsung SystemInfo](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/systeminfo-api.html) and [Samsung TVWindow](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/tvwindow-api.html).

## Preference migration and recovery

The new `frameos.launcher.v2` schema contains order, custom/pinned app identities and last focused item. The original `frameos.launcher.v1` value is retained for rollback. Old replacement slots migrate to their same stable IDs. Repeated native IDs are deduplicated; an old custom pin takes precedence over an equivalent default shortcut. Removing a pin never uninstalls its native app.

Backup format v3 exports the new dock model. Formats v1 and v2 remain importable. Existing settings, widgets, organiser data, hidden media, autoplay and other media preferences retain their established validation/migration. Import saves and verifies a recovery copy before changing any preference and restores prior section bytes on partial failure, including failure at the final dock write. No TV preferences or media files were removed.
