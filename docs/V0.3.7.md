## Thumbnail strategy

1. Resolve the selected file through Tizen in read-only mode. Record its actual URI and optional native `fullPath`; fail visibly if unavailable.
2. Query existing Content metadata with at most four narrow exact filters: resolved URI, distinct native absolute path, decoded URI path, then filename (maximum 16 candidates). A filename result is usable only when its full canonical path matches the resolved source or actual native path. No filename-only cross-drive matches and no USB indexing scan.
3. Test all indexed thumbnail URIs for successful image decoding. If no image works, native creation requires a matched Content object, an available API and confirmation of the existing `content.write` declaration in the installed package. Permission/unsupported/timeout failures stop repeated native attempts until Retry or invalidation.
4. Check an existing same-basename JPG and a validated `.frameos-thumbnails.json` import before spending time on HTML video decoding.
5. Where `canPlayType` advertises support, create a muted offscreen HTML video, seek to 15 seconds or 20% for short clips, wait for decoded pixels, capture a 320×180 JPEG and release the decoder. Timeouts, browser media errors, unsupported formats, blank frames and canvas security failures are recorded. AVPlay never enters a canvas capture path.

Samsung's [Content API documentation](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/content-api.html?device=htv) requires `content.write` for native thumbnail creation and a valid indexed Content object. API presence alone does not establish USB indexing or codec eligibility. `scanDirectory` capability is displayed but never invoked. The existing checkpoint already selected the v0.4 packaging policy containing `content.write`; **this patch changes no privilege or CSP declaration**, requests no filesystem write permission and does not alter original media. Creation fails closed if its installed declaration cannot be read.

Only the existing visible/near-visible card window requests thumbnails. The service retains one extraction slot, a maximum queue of 36, 128 memory records and 256 persistent records / 8 MiB of estimated payload. Positive entries expire after one day; precise negative outcomes after five minutes. Identity includes storage, path, size and modification time. Changed metadata invalidates that identity. Old silent null records are retried once. Manual Retry cancels obsolete work for that file, clears RAM/persistent outcomes and resets provider capability failures while preserving serialization. Playback pauses extraction; removal/view cancellation discards late results. Complete video files are never cached.

Readable images are compacted into app-private JPEG cache when canvas permits it. If a local image renders but canvas readback is denied, cache its validated file reference and verify again on rendering. IndexedDB denial/quota/stalls degrade to bounded memory caching. Desktop restart tests establish this browser path, not Samsung private-storage persistence.

## Diagnostics on the TV

Open a USB folder with videos. Hold OK on a video → **Thumbnail Diagnostics**, or open Settings → USB diagnostics → **Advanced: Thumbnail Diagnostics**. There was no separate Advanced tab in the existing interface, so this uses its existing diagnostics section.

The panel shows actual path/source URI, storage, extension, accessibility, native find/create/scan availability, privilege declaration, exact indexed match, latest method/error, final URI, cache outcome and actual rendering status. Previous/Next selects a video; Retry bypasses its cached outcome. **Earlier details / More details** scroll the bounded facts, preview and attempt history with the remote. Records are memory-only, capped at 64 videos with 16 attempts each. Selected failure stages are also logged to the developer console.

### Optional Windows helper

For a PC-accessible folder, use the existing helper. `--output` writes the manifest and snapshots separately, `--file` can select a sample, and omitting `--recursive` processes only that directory. Paths with spaces are passed as arguments without a shell. One extraction runs at a time.

```powershell
Set-Location 'C:\Users\revil\StudioProjects\frameos\Project-FrameOS'
$thumbnailFfmpeg = (Get-ChildItem -LiteralPath '.\artifacts\tools\ffmpeg\portable' -Filter ffmpeg.exe -Recurse | Select-Object -First 1).FullName
$thumbnailFfprobe = Join-Path (Split-Path $thumbnailFfmpeg) 'ffprobe.exe'
node scripts/generate-thumbnails.mjs 'C:\Users\revil\Desktop\1.FRIENDS\Season 01 (1994-95)' --file 'EP01_Pilot.mp4' --output '.\artifacts\v037\offline\Season 01 (1994-95)' --ffmpeg $thumbnailFfmpeg --ffprobe $thumbnailFfprobe
node scripts/generate-thumbnails.mjs 'C:\Users\revil\Desktop\1.FRIENDS\Season 03 (1996-97)' --file 'EP01 The One with the Princess Leia Fantasy.mkv' --output '.\artifacts\v037\offline\Season 03 (1996-97)' --ffmpeg $thumbnailFfmpeg --ffprobe $thumbnailFfprobe
```

To import on the television, place each generated folder's `.frameos-thumbnails.json` and `.frameos-thumbnails` directory **beside the matching unchanged videos on the USB**, retaining names and metadata. Only these generated helper files need copying; the videos are not rewritten. The manifest stores name/relative path, stable identity, byte size and mtime; the app accepts only the bounded versioned schema and hashed relative JPEG paths. Retry after copying. No PC or server needs to remain powered on. A USB attached only to the TV must first be made accessible to Windows or receive these sidecars separately; the helper does not assume remote TV-drive access. Import to the physical Samsung USB filesystem still needs the acceptance test below.
