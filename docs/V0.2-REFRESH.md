# FrameOS v0.2 refresh: USB fixes and supplied artwork

Clock follow-up: **Settings ? Clock** now selects 12-hour (default) or 24-hour time, plus 18 time zone choices including device local time. Brisbane remains the default zone. Clock/date and daylight saving follow that zone; weather uses its selected city with the chosen time format. Settings migrate safely and persist after reload. Current validation: **79 unit/pipeline tests, 18 browser tests**, production and signed Tizen builds passed. The latest signed build is `artifacts/releases/v0.2-clock/frameos-v0.2-clock.wgt`; prior signed releases below remain rollback points. No TV installation was performed.

The refresh includes all 47 supplied wallpapers, the supplied logo/app SVGs, seven gradient app tiles, a bold bundled serif clock, hourly weather, restored separators, a Media/Down prompt, one-page vertical transitions, network status, Close FrameOS, animation controls and a temporary FPS counter. Settings separates Appearance, Clock, Wallpapers, Weather and USB diagnostics. Wallpaper choices are bounded to 12 thumbnails per page; the removed old collection falls back to the first new photo while retaining theme, motion and city preferences.

## USB findings and remaining uncertainty

Two concrete native compatibility bugs were found and corrected:

1. `TizenMediaAdapter.update()` used `{ ...storage }` to retain `FileSystemStorage` objects. Native WebIDL properties can be inherited/non-enumerable; that copy loses `label`, `type` and `state`, so the subsequent `MOUNTED` filter can return no drives. The adapter now reads each documented property explicitly. Unit and production-browser regressions use prototype getters with zero own enumerable properties.
2. Each directory entry's `fullPath` was required to begin with its virtual storage label. A native absolute device path was silently rejected. Browsing now retains a virtual path constructed from the resolved parent plus the unmodified native filename. Resolved directory URIs retain real device locations without assuming `/media` mount paths. Malformed names are counted; rejecting every returned entry is an explicit error.

Native API exceptions previously appeared alongside the disconnected prompt. Discovery, resolution and enumeration failures now remain errors; Settings retains the operation and the native error's name/message. A genuine empty directory and a disconnected drive remain separate states. Lazy reads, read mode `r`, the directory cache, stale-request guards, dynamic drive labels, removal invalidation and bounded rendering are preserved.

**Physical-TV USB behavior is not yet confirmed.** SDB identified the expected QA32LS03TBWXXY, but the existing app's debug command did not return a debugging endpoint. No new app was installed. The exact properties, mounted storage state and privileges of the currently installed application therefore remain uncertain until the new in-app diagnostics run on the TV. Browser fixtures and successful signing do not establish that evidence.

The external Tizen source manifest has no filesystem privileges. The original signed v0.2 archive does declare the read-only policy; a direct Tizen Studio build of the external source can differ from pipeline packaging. Diagnostics reads the manifest inside the running installed package rather than assuming which package was deployed.

During this work the external manifest was edited separately to add author details, change its widget URL and select `frameos-icon.png`. The refreshed reviewed baseline preserves those edits. Its SHA-256 is `df9616f0175d656253ad7f55a534f07f6dca6c8e62be0e5695bd6d15fd54dd78`. Application `TdjFk7yyVS.frameos`, package `TdjFk7yyVS` and widget version `1.0.0` are unchanged. The matching existing certificate profile remains `revilodev-frameos`; the older profile named `frameos` has the wrong author for this application.

The canonical packaging policy is [policy-v0.2.json](../tizen/policy-v0.2.json), implemented by [tv-policy.mjs](../scripts/tv-policy.mjs). [The precise diff](../tizen/config.xml.v0.2.diff) and [resulting manifest](../tizen/config.xml.v0.2.preview) add only:

- `http://tizen.org/privilege/filesystem.read`
- `http://tizen.org/privilege/externalstorage`
- `http://tizen.org/privilege/internet`
- Access to `https://api.open-meteo.com`, with same-origin requests allowed for reading the packaged manifest in diagnostics.

No filesystem write permission is requested. If Samsung denies storage listeners because they require write permission, the read-only snapshot fallback runs every five seconds while Media Hub is open. It stops when Home returns. No USB contents, TV settings, firmware, autostart or certificates are modified. The external source configuration is never overwritten.

The output validator was extended for Vite's `JSON.parse` catalog emission and SystemJS-relative font URLs. All 141 wallpaper assets, four SVGs, the font/license and runtime scripts must be present before packaging. This prevents a successful web build from producing a package with missing dynamically referenced artwork.

The original uploads are retained in ignored `artifacts/imports/user-assets-2026-10-20/wallpapers/`. The 134 MB originals become approximately 16 MB of TV JPEGs, thumbnails and baked blur layers. AVIF is converted offline for Chromium 69; runtime code never attempts to decode it. No launcher path loads all 47 full-resolution photos simultaneously.

Existing rollback artifacts remain untouched: `artifacts/releases/v0.1/frameos-v0.1.wgt`, `artifacts/releases/v0.2/frameos-v0.2.wgt`, their verification records, and Git checkpoint `93c110a`.

## Physical TV check after approved installation

1. Install only after approval: run `npm run deploy:tv` from this React repository. This is the command that updates the TV.
2. Open **Settings → USB diagnostics → Rescan USB** with a drive attached. Confirm Tizen runtime, filesystem API and filesystem read privilege all show **Yes**.
3. Check the reported storage labels/types/states. A USB drive must be reported as `EXTERNAL` / `MOUNTED`. The label is discovered dynamically, never hardcoded.
4. Check resolved root paths and nonzero entry counts. Use **More ↓ / ↑ Earlier** to read the full native error/event history. If scanning fails, retain the exact operation, native error name and message; do not reformat the drive or add write permission to bypass the error.
5. Back to Home, select a bottom dock tile and press Down. Root files should appear; Enter opens folders, Back returns to the parent and restores focus. MP4/MKV details must retain the actual name, virtual path, URI, storage, size and extension. Playback remains outside this release.
6. Insert/remove a drive while Media Hub is visible; verify entries and details clear on removal. If native listeners are denied, allow up to five seconds plus the native call duration for snapshot discovery. Test multiple drives, empty/nested directories, long names, Refresh and a large directory.
7. Check all four wallpaper pages, weather/location/cache behavior, seven dock apps, Settings navigation, animation modes, FPS and the exit confirmation. The Wi-Fi-shaped control reports network availability; it does not change Wi-Fi settings. The power-shaped control closes FrameOS, leaving TV power to the remote.
