# FrameOS v0.4.1 launcher corrections

Prepared 25 October 2026 for Samsung QA32LS03TBWXXY, Tizen 5.5 / ARMv7 / Chromium 69. No v0.4.1 package was deployed or run on the TV during preparation.

Source checkpoint: `checkpoint/pre-v0.4.1-20261025`, commit `64622f9ae17eba48a1a8abe2f27595936ff370fa`. This commits the complete previous working source, including its compact dock spacing correction, before the v0.4.1 edits.

## Root causes and corrections

| Problem | Cause | Correction |
| --- | --- | --- |
| Up opened app options | The dock direction override explicitly called its context-menu handler. Duplicate global navigation listeners were not the cause. | Removed that override for every dock action, including HDMI pins. Up now follows the spatial focus rows. Dock ContextMenu/F10 also cannot substitute for a hold. The single navigation listener and Art Mode's capture-only wake listener remain. |
| Unreliable dock holds | The old recognizer depended on assumed remote repeat/release behavior. | Hold editing is disabled by default. Advanced → Remote input diagnostics can measure two sustained Select down/up pairs on the actual input device. Only verified session evidence enables a single 700 ms hold/release gesture. Failed or missing releases disable it for the session. No alternative directional, double-OK or repeated-OK editing shortcut is installed. |
| HDMI could not be pinned | Preferences only represented built-in destinations and installed app pins. | Added a separate `source` action and stable `source:HDMI:<number>` identities, with versioned source descriptors and revalidation against TV-reported inputs before launch. |
| Dead Samsung Settings tile | An installed Samsung component is not proof that a public application launch is permitted. | The dock Settings tile opens FrameOS Settings immediately. TV & Sources contains one guarded standards-based Settings application-control test. Samsung Home remains the native Settings escape. |
| Browser icon disappeared after builds | The requested SVG existed only in generated `dist`. | Copied the exact SVG into `public/assets/browser.svg`; the component references the maintained asset. |
| Focus border lost corners | The icon clipping surface, rectangular decorative overlay, focus treatment and scrolling viewport shared clipping/painting responsibilities. Focus expansion also changes visible bounds. | Added a clipped rounded artwork surface and a separate sibling ring, both inheriting the tile's geometry. The ring is inside the un-clipped button, has no layout footprint, and stays above adjacent tiles. Transition-end scrolling keeps the expanded tile visible. |
| Theme inconsistency | Many screens used hardcoded dark surfaces or white text instead of semantic colors. | Added shared surface, text, selection, control, field, scrim, focus and player tokens; corrected Light/Aqua contrast and theme previews during visual inspection. |
| Complicated Settings | Launcher tools and independent Clock/Weather/USB tabs mixed unrelated controls. | Six main sections with focused child pages, section-aware channel navigation, remembered selections and Back returning to the parent before closing. |

## Dock input

- Left/Right moves between applications. Up moves toward widgets/top controls. Down focuses Media, then Down or Select enters Media Hub.
- With hold editing disabled, normal Select activates immediately and held-key repeats are suppressed.
- After successful remote diagnostics, short Select activates promptly on release, without a fixed hold delay. A sustained 700 ms Select opens editing on release; it never also opens the app. The editing menu exposes Move, Remove where allowed, Open and information.
- In Move Mode, Left/Right changes position, Select saves and Back cancels. Art Mode stays first; Art Mode, TV and All Apps remain protected.
- Focus changes cancel stale timers. Blur/visibility loss cancels pending gestures. A missing release watchdog disables editing and retains the held-key latch, including for firmware repeats that incorrectly report `repeat=false`.
- Remote diagnostics use session-only observed keydown/keyup timestamps, not a firmware/model allowlist. They do not persist a guessed capability across restarts. No calibration is attempted during normal startup.
- Existing explicit Add/Remove actions in All Apps remain available. There is no Up/Down editing fallback.

Desktop tests verify clean and broken event streams, numeric Tizen Select codes, repeated events without repeat flags, cancelled gestures, move confirm/cancel, missing releases and normal short activation. The physical TV's hold stream remains unverified, so production editing starts disabled.

## HDMI sources and viewing

All Apps now has a **Sources** section. It contains HDMI ports actually returned by `VIDEOSOURCE`, including reported connection status. Each card provides direct Open and Add to Dock; pinned state is visible and duplicate additions are ignored. No HDMI input is represented as an installed application.

Pinned sources are normal dock tiles. Both direct launch and the Source picker resolve the requested type/number against a fresh reported list before calling the existing `tvwindow.setSource()` and full-screen `show(..., 'MAIN', 'FRONT')` path. The Source picker uses large direct cards with spatial remote navigation, minimal labels and a TV escape.

The full-screen viewing state hides launcher chrome and keeps Back/TV controls. Back hides the TVWindow before restoring the original source card, All Apps control or dock pin. Cancelling during discovery prevents a later source change. A late display callback is hidden again. Errors offer Samsung Home → Source.

The on-screen status says **Viewing requested**, not that HDMI playback succeeded. API acknowledgement does not establish an image, global Samsung input ownership, signal presence or visible full-screen playback. Physical picture and Back behavior still require acceptance on the TV.

No verified native HDMI-viewer transition was established. SDB connected to the expected TV, but the installed app's inspector request did not return a debugging endpoint and was stopped. No guessed native viewer ID or undocumented launch data was used. The documented TVWindow path and the working `com.samsung.tv.csfs` escape are retained.

## Native Settings result

The old direct component launch is not used by the dock. The final supported test constructs `ApplicationControl('http://tizen.org/appcontrol/operation/setting')` and calls `launchAppControl(control, null, ...)`, allowing the public system resolver to choose its registered handler. It never substitutes another guessed Samsung ID.

The test is explicit, bounded, recorded in launch diagnostics and guarded against repetition, including across restarts when storage is available. Denied, unsupported, absent and accepted API outcomes have tests. An accepted callback is explicitly unverified. No native Settings visibility was established on the physical TV in this session; therefore the dock's reliable FrameOS Settings fallback remains active. The top-right gear always opens FrameOS Settings. TV → Samsung Home still provides native TV Settings.

References: [Samsung Application API](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/application-api.html), [Tizen common application controls](https://github.com/Samsung/tizen-docs/blob/master/docs/application/web/guides/app-management/common-appcontrols.md), [Samsung TVWindow API](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/tvwindow-api.html).
