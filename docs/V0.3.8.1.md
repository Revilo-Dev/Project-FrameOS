## Thumbnail diagnosis: established defects and the remaining device question

The complete source path was inspected: USB enumeration and native file
resolution in `TizenMediaAdapter`, `Content.find` / `thumbnailURIs` /
`createThumbnail` in `TizenThumbnails`, image validation and HTML frame capture,
the fallback provider, bounded IndexedDB cache, lazy MediaThumbnail cards and
the on-TV diagnostics panel.

Two concrete defects were reproduced and corrected:

1. **Persistent failures survived USB invalidation.** `ThumbnailService.invalidate`
   cleared memory and provider state but left persistent records intact. A drive
   reconnect could therefore restore a negative result without checking newly
   imported screenshots. The new integration test reproduces a cached failure,
   makes a screenshot available, invalidates the drive, and verifies the new
   image also survives service restart. Invalidation now removes the relevant
   persistent records. The strategy key is versioned to bypass old outcomes.
2. **The source priority was wrong.** Native Content queries and native creation
   ran before USB imports. Existing native results could mask preferred offline
   screenshots; failed/slow native operations delayed every visible card.
   Imported images now come first and must decode successfully. Integration
   tests verify zero native calls for an imported video, and fall-through to
   native images when the imported JPEG fails to load.

Additional repairs: a cancelled manifest read no longer caches an empty result
for five minutes; image-element failures become time-limited negative cache
entries; native capability failures expire after five minutes; focused jobs move
ahead of nearby work. Existing single-job extraction, bounded queues, view
cancellation, image resource cleanup and playback pausing remain in place.

**The exact firmware failure for the user's original USB file has not been
determined.** SDB successfully connected to `192.168.0.23:26101` and reported
`QA32LS03TBWXXY`, Tizen `5.5`. The installed-app inspector attempt did not yield a
debug endpoint; the bounded retry returned exit 1, `closed`. No new package was
installed. Consequently there is no physical-device evidence that Content.find
indexes those USB files, createThumbnail succeeds, an HTML decoder reads those
URIs, or that the TV image element renders the generated JPEGs. This release
must not be described as physically verified or as proof of native extraction.

Samsung's [Content API reference](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/content-api.html)
requires a Content object for `createThumbnail` and the `content.write`
privilege. That privilege already existed in the established v0.3.8 packaging
policy; **no privilege was added**. Creation remains guarded by the installed
manifest declaration and an exact indexed file match. No USB scan is performed.
Filesystem resolution and AVPlay playback support do not establish successful
HTML frame capture. AVPlay surfaces are never copied into canvas.

## Independently usable Windows fallback

See [the utility guide](../scripts/media-thumbnails/README.md). On this machine:

```powershell
.\scripts\media-thumbnails\Generate-Thumbnails.ps1 `
  -FFmpeg "$PWD\artifacts\tools\ffmpeg\ffmpeg-9.0.2-essentials_build\bin\ffmpeg.exe" `
  -FFprobe "$PWD\artifacts\tools\ffmpeg\ffmpeg-9.0.2-essentials_build\bin\ffprobe.exe"
```

Select the USB drive/video directory and type `YES` after reviewing the write
destination. The utility recursively generates 320 x 180 JPEGs, avoids nearly
black samples, writes manifests, skips unchanged files and reports failures.
Only FrameOS thumbnail/manifest files are written. Videos are read without any
rename, transcode, deletion or modification. Cancellation was tested to leave
the entire selected test directory unchanged; an approved repeat skipped the
existing video. A 20-second black-opening test video produced a nonblack frame
from a later interval. FFmpeg selection uses its documented
[thumbnail, blackframe and metadata filters](https://ffmpeg.org/ffmpeg-filters.html).

Reconnect the USB to the TV and open Media Hub. Matching uses per-directory
relative names, file size and available modification times, with two seconds of
filesystem precision tolerance. It does not depend on Windows letters or Tizen
mount paths. Large folders use a tiny index and name-based manifest shards,
each bounded to 256 KiB; only the selected shard is read. A 10,000-entry manifest
round-trip test passed. The TV never writes these files and no PC/server is
required during viewing.

Source priority is: validated imported USB JPEG (including legacy sidecars),
validated existing Tizen thumbnail, validated native creation / successfully
decoded nonblank HTML frame, then the existing video icon. A broken image is
removed immediately. A screenshot is never replaced by invented artwork.

## Art Mode and system protection

Art Mode is the first of the existing seven dock tiles and retains the dock's
expansion/animation. Selecting it enters an internal UI state. Home, its clock
instance and wallpaper remain mounted. Only the wallpaper and existing clock
are visible; the date, dock, widgets, top bar, Media Hub and decorative overlays
are hidden. The date retains invisible layout space so the time's existing
position does not shift. No separate clock, wallpaper or settings store exists.

One Select/Enter, Back, directional key, click anywhere or touch restores Home
and focus to Art Mode. Capture-phase handling consumes the wake input and its
repeats, preventing a held Select from reopening Art Mode. Tests check the same
clock DOM instance, equal clock bounds/font/size, identical wallpaper URL, widget
restoration and normal navigation after waking, at 1920 and 960 pixels.

No screensaver API call existed in this checkout, including in AVPlay. No
screensaver, power or standby override was added or removed. Power and volume
remain system keys. Native Samsung Art Mode launching was removed from the
FrameOS action path. Existing Gallery remains its simple native-app shortcut;
no collections, slideshows, brightness, mats or power interception were added.

## Media Hub and diagnostics

This checkout initially used six columns (four in compact layout) and lacked a
grid selector. The patch supplies the requested five-column default and
persistent 3/4/5/6/7 choices in Options. Navigation rows and virtual card geometry
use the same selected column count. Folder backgrounds, directory caching/lazy
loading, continuous scrolling, hidden items, episode order, player controls,
system volume and channel seeks are covered by the existing regression suite.
No selectable URL/path bar was added.

Focus a video, hold OK, then choose Thumbnail Diagnostics, or open Settings >
USB diagnostics > Advanced: Thumbnail Diagnostics. It shows original virtual
file path, resolved extractor URI, selected thumbnail source/method, filesystem
resolution result, frame/image production, output image URI/decode result,
last error, rendering result and cache state. Retry bypasses cached failures and
manifest metadata without a directory rescan. A successful native file resolve
means a File object was obtained; successful JPEG decode/card rendering is
reported separately and is the relevant image acceptance evidence.
